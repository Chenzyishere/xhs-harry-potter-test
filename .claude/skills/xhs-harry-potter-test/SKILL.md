# 霍格沃茨分院帽测试 H5 产品开发

把一个"你属于哪个学院"的想法，做成能卖、能传播、能复制的产品。它是「测试 H5 模板」在魔法学院题材上的一个实例。

## 何时使用

- 用户要做分院帽、魔法学院、"你是哪个学院"类测试 H5
- 目标平台是小红书 / 微信，靠虚拟商品变现
- 追求单点跑通、快速上线，而不是做通用平台

## 先对齐三件事

不要直接开始写代码。先确认：

| 问题 | 默认推荐 |
|---|---|
| 有没有店铺？ | 没有就先去办个体户执照，7–10 天下证，期间用"内测免费"过渡 |
| 怎么变现？ | 低价虚拟商品。**按 1.9 / 2.9 设计**，0.99 常卡平台最低售价 |
| IP 怎么处理？ | 见下方「版权红线」。**免费引流自用可以用原著名，挂商品收费前先改通用词** |

## 版权红线（本题材独有，务必先读）

哈利·波特、霍格沃茨、分院帽、四个学院名都是**华纳兄弟的注册商标**，和历史人物（公有领域）完全不是一回事。

- **免费引流 / 内测阶段**：直接用原著名，风险相对可控，属于粉丝二创范畴
- **挂商品收费阶段**：侵权风险显著上升。建议把「霍格沃茨 / 分院帽 / 格兰芬多」等专有名词换成「魔法学院 / 学院测试 / 勇气学院」这类通用表述，或提前做一次法务评估
- **配图**：不要用电影剧照、官方插画，用 AI 生成或纯文字排版

这一条是硬约束，不是"以后再想"。详见 [references/launch-playbook.md](references/launch-playbook.md) 的「合规红线」。

## 三个不可动摇的原则

**1. 结果卡就是产品本体。**
用户付费买的不是测试过程，是那张能发出去的分院卡。所有设计决策都问一句：这能不能提高截图分享率？

**2. 结果文案全部预写，不做实时 AI 生成。**
4 个学院的画像、相似点、金句提前写好。稳定、零成本、审核可控、无延迟。AI 只在生产期批量出初稿，然后人工改。

**3. 学院文案踩在粉丝共识上，不 OOC。**
和历史人物不同，四个学院有极其确定的原著人设。**斯莱特林不是"坏"，是"野心 + 精明"；赫奇帕奇不是"平庸"，是"忠诚 + 靠谱"**。写反了，路人无感、原著粉会喷，两条受众一起丢。检验方法：写完后问一句"一个 10 年哈迷看了会点头还是会骂"。

## 六阶段流程

### 阶段 0 · 竞品拆解

拿到竞品链接后，先确认它到底是什么：

- 小红书分享链接常见会跳到 `goods-detail`（虚拟商品）或 `discovery/item`（笔记）
- 抓页面拿不到内容时（SPA + 登录墙），**从客服话术反推**。典型话术里藏着：解锁方式（密码/验证码）、是否限次（"不限使用次数和时间"）、复购钩子（"好评送其他工具"）、托管方式（html2.link 这类第三方 H5 托管）

产出：一张"它在卖什么、怎么交付、怎么引流"的清单。

### 阶段 1 · 内容设计

详见 [references/content-design.md](references/content-design.md)。

核心动作：
- 定 **4 个双极维度**：勇气/谨慎、野心/淡泊、理性/感性、忠诚/自我（对应四学院精神）
- 写 **4 个学院**，每个挂一个情绪标签 + 学院动物 + 创办人
- 写 **16 道题**，每题 4 选项，选项要具体、有画面感、带魔法场景
- 给每个学院写 **3 个相似点 + 1 句金句 + 1 句人生建议**

### 阶段 2 · 技术实现

纯静态，四文件，无框架、无构建、无后端。详见 [references/code-scaffold.md](references/code-scaffold.md)。

```
index.html
css/style.css
js/data.js     ← 所有内容在这里，改产品不动代码
js/app.js      ← 计分、匹配、出图
```

必须实现的清单：
- 解锁页 → 开始页 → 做题页 → 结果页
- 「上一题 / 下一题」，可回退改答案，提交时统一算分
- 答题进度存 `sessionStorage`，刷新不丢
- 结果页四维雷达
- Canvas 生成 1080×1440 分院卡
- **iOS 长按保存浮层**（Safari 不支持 `a[download]`）
- 一键复制晒单文案
- 页面可滚动 + 底部安全区

### 阶段 3 · 解锁与交付

用**校验位验证码**，不用固定密码：

- 格式 `前缀 + 6 位随机 + 1 位校验位`，校验位由主体 + 盐值散列得出
- 本地离线批量生成，卖一单发一码，零后端
- 主密码留一个给自己测试
- 发码工具放 `tools/` 目录并加进 `.gitignore`，不随站点公开

### 阶段 4 · 部署

GitHub Pages 起步，阿里云 OSS 正式。详见 [references/launch-playbook.md](references/launch-playbook.md)。

### 阶段 5 · 冷启动

新建专号，不要用老号做实验。详见 [references/launch-playbook.md](references/launch-playbook.md)。

### 阶段 6 · 内容运营与推流

产品上线后的推流：标题套路、硬广软文配比、发帖节奏、商品配图。详见 [references/content-marketing.md](references/content-marketing.md)。

## 验收清单

上线前逐条过：

- [ ] 4 个学院**每一个都测得到**（跑 `tools/verify-reach.js` 穷举验证）
- [ ] 结果页在小屏（iPhone SE）上按钮不被裁、能滚到底
- [ ] iOS 真机点保存，能长按存图
- [ ] 做到一半刷新，进度能恢复
- [ ] 瞎编的验证码被拒绝，主密码能进
- [ ] 分享卡文字不溢出、不压边
- [ ] 复制文案在微信内置浏览器里也能成功
- [ ] 4 个学院的文案没有 OOC（尤其斯莱特林、赫奇帕奇）

## 已知坑

| 坑 | 后果 | 对策 |
|---|---|---|
| `a[download]` | iOS 完全无效，传播链断 | 检测 iOS，改长按保存浮层 |
| `#app { overflow:hidden }` + 绝对定位 | 结果页底部被裁，按钮点不到 | 页面级 `overflow-y:auto`，`#app` 用 `100dvh` |
| 固定密码 | 链接一传全网免费 | 用校验位验证码 |
| 只用正向维度计分 | 中间态不可达，部分学院永远匹配不到 | 双极维度 + 归一化后算欧氏距离，**上线前验证可达性** |
| 学院文案 OOC | 原著粉差评、路人无感 | 踩粉丝共识，写前过一遍哈迷视角 |
| 直接挂原著名收费 | 商标侵权风险 | 免费引流用原名，收费改通用词 |
| 结果卡没引流入口 | 图被转发但没人知道去哪测 | 卡底写「小红书搜索『品牌名』」 |
| 多账号/批量私信 | 被判营销号限流 | 一机一号，前 3–5 条纯内容不带链接 |

## 换题材

这套代码是"测试 H5 模板"。换一个题材只需改 `js/data.js`：

1. 换 `figures`：学院/人物名、文案、`vector`
2. 换 `questions`：题目和选项，`effect` 保持四维结构
3. 换标题、品牌名、晒单模板

计分引擎、页面、分享卡、解锁逻辑全部复用，不动 `js/app.js`。

可复用的题材方向：明星、CP 配对、古风人设、二次元、职场人格、宠物性格、家装风格、旅行人格。
